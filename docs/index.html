carp-coordinator

An event system for Carp, in three layers that can be used separately or together.

(load "git@github.com:carpentry-org/carp-coordinator@master")

Layers

  • Dispatcher — the switchboard. handlers subscribe and get an id back; broadcast! calls each of them synchronously. handlers are snapshotted first, so a handler may subscribe or unsubscribe mid-broadcast without disturbing the one in flight.
  • Scheduler — the clock. a binary heap of TimedEvents ordered by due time, with one-shot and periodic tasks and cancellation by id.
  • Coordinator — the two above plus a FIFO queue, driven by a throttled run loop. tick! drains the queue exhaustively, so events raised by handlers run in the same tick.

Events

Events are whatever type you make them, usually a sumtype. handlers return a Result, and the coordinator counts the failures rather than swallowing them.

(deftype AppEvent (Msg [String]) (Stop []))

(let-do [c (Coordinator.new)]
  (Coordinator.subscribe! &c &(fn [ev]
    (match ev
      (AppEvent.Msg s) (do (IO.println s) (Result.Success ()))
      (AppEvent.Stop)  (do (Coordinator.stop! &c) (Result.Success ())))))
  (Coordinator.dispatch! &c (AppEvent.Msg @"hello"))
  (Coordinator.schedule! &c (AppEvent.Stop) 1000l)
  (Coordinator.run! &c))
